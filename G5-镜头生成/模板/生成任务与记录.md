# 生成任务与记录

## 本次任务

- 项目、集场、镜号与交付范围：
- 分镜、导演要求及当前有效版本：
- 本次目标、保留项、待定事项：
- 执行授权、批次、次数或消耗边界：

## 生成分段规划

按本次分镜原顺序逐对判断合并或拆分，综合连续动作、状态、对白和时长、切点控制、参考资产、入口能力及返工代价。已确认拍法与资产保持不变；有缺口或实施冲突时先提出具体影响。

| 生成段 | 原镜号 | 合并或单镜理由 | 估算时长 | 参考资产版本及职责 | 切点、声音衔接与待确认事项 |
|---|---|---|---|---|---|

- 相邻镜头逐对合并／拆分及具体理由：
- 本次范围镜号覆盖、用户指定范围及分镜版本：
- 台词估时依据：非空白字符数（含标点）÷默认4字符/秒、特殊停顿与动作重叠；语速调整或试读／已选配音实测另记：
- 已核实的模型、模式、入口、时长与参考能力：
- [机器检查方案文件](生成分段方案.json)及对应分镜摘要：

生成段安排和逐镜提示词需分别核对；无完整方案不得交正式视频提示词。实际生成按授权执行。

## 任务与输入

每个生成任务独立成节，关联实际剪辑镜号，不为生成拆分重新编号全部镜头。

### 任务

- 任务ID、镜号及前后关系：
- 已核对的生成分段方案、当前段号与原镜号：
- 平台、模型准确版本、模式与实际入口：
- 对应官方规范、读取日期、本地模板与版本：
- 画幅、时长、分辨率、声音及其他实际参数：
- 实际参考文件、版本、上传顺序、引用标签及职责：
- 起止状态、动作与运镜难点、必要衔接：
- 提示词正文文件、最终交付Markdown（`delivery_file`）、版本与校验报告：
- 初稿处置（`draft_review.disposition`）：有问题或改动用`revised`并单独保存完整新稿；实际独立复检无问题、`issues: []`且字节未变可用`accepted_unchanged`保留已审原文件。已审SHA256、实际复检记录和当前输入指纹：
- 稿件状态（草稿／正式稿）与生成条件（具备／尚缺）及对应依据：
- 非投喂检查依赖（`dependency_files`）、职责及摘要；同场衔接依据（`continuity_context`）：
- 实际画面文字转交索引（`post_handoff_file`）与记录ID；无转交时说明：
- 执行条件、限制及缺口：

|---|---|---|---|---|---|---|
| | | | | | | |

提交后追踪同一任务；超时先查已有任务，核对后再决定是否重试。只准备提示词时不填写虚构的任务ID或输出。
